# GeoWords — пилот правила 1 + 6 (ветка PR #8)

## Подтверждённое продуктовое решение

**На каждом учебном шаге: один оригинальный авторский геоворд из тетради + шесть разных сгенерированных слов = семь завершённых слов.** После седьмого слова автоматически открывается следующий авторский геоворд следующего шага.

- Решение считается завершённым, даже если ребёнок ошибался и затем исправлял буквы. «Семь безошибочных» **не** вводится.
- Повторное решение авторского задания не даёт второй зачёт.
- Повторное решение сгенерированного слова не даёт второй зачёт.
- Нельзя зачесть генерации, пока не завершён оригинальный геоворд этого шага.
- Семь слов должны быть разными (шесть дополнительных слов не повторяют слово из тетради).
- На 7/7 переход автоматический: сообщение о завершении → факты для следующего оригинального задания → кнопка «I'm ready» для открытия карты.
- Ошибки не обнуляют текущий шаг.
- После финальных 7/7 остаются тренировочные варианты **без новых зачётов**.

## Что действительно готово в пилоте

Из исходной авторской тетради **Level 2 Rivers** импортированы первые три задания. Карты извлечены из PDF без вплавленных букв; координаты букв вычислены по их оригинальному PDF-текстовому слою. Порядок подсказок, слова и определения проверены.

| Учебный шаг | Авторское слово | Факты, открывающиеся после оригинала | Шесть разных дополнительных слов |
|---|---|---|---|
| 1 | CHANNEL | Нил | DELTA, BASIN, SOURCE, MOUTH, STREAM, SEDIMENT |
| 2 | FLOODPLAIN | Амазонка | EROSION, RAPIDS, VALLEY, CURRENT, FLOOD, MEANDER |
| 3 | RAINFOREST | Миссисипи | ESTUARY, TRIBUTARY, WATERFALL, WETLAND, DRAINAGE, RESERVOIR |

**Важно:** авторская Rivers последовательно вводит Нил, Амазонку и Миссисипи на первых трёх оригинальных заданиях. Янцзы появляется позже. Мы не меняем оригинальный порядок ради раннего демо.

Внутри шага первый оригинальный геоворд вводит материал, а шесть практических заданий помогают закрепить. Данные `introFacts` для второго и третьего оригинала взяты из `nextFacts` предыдущей авторской задачи.

Готовые **11 Mountains** не переписаны и сохраняют прежние ключи прогресса `geowords_completed_*`.

## Техническая реализация

- `engine/geowords.js`: `newProgress`, `normalizeProgress`, `nextAuthoredPuzzleId`, `nextWordId`, `markSolved`, `stepScore`.
- `data/courses.js`: `authoredPuzzleId` + ровно шесть `wordIds` на шаг.
- `data/rivers-authored.js`: три оригинальных задания с импортированными PDF координатами, текстами и фактами.
- `assets/rivers-authored-1.webp` … `-3.webp`: оригинальные карты без букв. Буквы отображаются как элементы интерфейса поверх карты.
- `app.js`: **один** сценарий игры и завершения для авторских Rivers и генераций; `playMode="rivers"`.
- `index.html`, `sw.js`: подключение оригиналов и их карт к PWA, включая offline precache.
- `scripts/validate-generator.mjs`: проверка 3 оригиналов + 18 генераций, автоматических переходов, повторов, миграции, сохранения и отсутствия дублирования слов.

### Прогресс v2

```json
{
  "schemaVersion": 2,
  "courseId": "rivers",
  "stepIndex": 0,
  "steps": {
    "nile": {"authoredSolved": true, "solvedWordIds": ["delta"]},
    "amazon": {"authoredSolved": false, "solvedWordIds": []},
    "mississippi": {"authoredSolved": false, "solvedWordIds": []}
  }
}
```

Счётчик каждого шага = `Number(authoredSolved) + solvedWordIds.length`, максимум 7. `stepIndex` пересчитывается из подтверждённых результатов, а не доверяется сохранённому индексу. Ранее использовавшийся в незамёрженной версии PR формат `version:1, solved:[]` читается с миграцией: прежние заработанные шесть слов сохраняются, но завершение **авторского** задания не выдумывается.

## Проверка в CI

```sh
node --check app.js && node --check engine/geowords.js && node scripts/validate-levels.mjs && node scripts/validate-generator.mjs
```

Дополнительная проверка на телефоне: оригинальный CHANNEL (буквы по координатам PDF) → 6 новых слов → автоматическое появление FLOODPLAIN; проверить, что после авторского решения показываются оригинальные факты, сохранение после перезапуска, повторные решения не добавляют очков, на ширине 320–360px нет ошибочного выбора соседних букв. После третьего шага тренировка остаётся доступной.

## Что НЕ готово: блокеры PR #8 перед продуктовым merge

Этот пилот реализует **согласованное правило 1+6**, но ещё **не является полноценной реализацией ТЗ v0.6**.

- Существующий экспериментальный генератор по-прежнему не моделирует `resolvesTo`, `containedBy` и семантическую однозначность. Нельзя делать вывод о качестве его подсказок по прохождению арифметических тестов.
- Пока используются два разных способа отображения карты: авторская графика для оригинала и ранняя программная подложка для сгенерированной тренировки. Нужны единые проверенные авторские карты/якоря v0.6.
- Глобальные Curriculum / knownFacts / knownPlaces и схема descriptors из ТЗ v0.6 ещё не реализованы.
- Импортированы **только первые три** оригинальных задания Rivers, а не вся тетрадь или весь каталог.
- Текущие примеры слов из чернового `data/dictionary.js` не утверждены автором.
- Полноценный headless Chromium / iOS Safari E2E тест этого обновления ещё не выполнен.

**Решение:** ревьюировать PR #8 как экспериментальный пилот. Не мержить в `main`, пока не устранены семантические P0 из ТЗ и не проведено детское/авторское тестирование.
