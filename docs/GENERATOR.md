# GeoWords — единое ядро, PR #8 (пилот после исправлений ревью)

## Что реализовано и проверено

**Правило автора:** один оригинальный геоворд из тетради + шесть различных автоматически созданных = семь завершённых слов на каждом учебном шаге. После 7/7 открывается следующий шаг автоматически. Ошибки выбора букв разрешено исправлять; они не обнуляют результат. Повторное прохождение исходного или созданного задания не добавляет зачётов.

Из исходной Level 2 Rivers импортированы три оригинальных задания:
- Шаг Нил: оригинальный **CHANNEL**, затем 6 разных тренировок.
- Шаг Амазонка: оригинальный **FLOODPLAIN**, затем 6 разных тренировок.
- Шаг Миссисипи: оригинальный **RAINFOREST**, затем 6 разных тренировок.

Авторские карты, оригинальные координаты букв, тексты и последовательность фактов сохранены. Чёрные **стрелки** (2 во втором, 3 в третьем пазле) извлечены из векторного слоя PDF и отображаются отдельно, поверх исходной карты.

Оригинальная последовательность введения знаний: после CHANNEL ребёнок получает факты о Ниле, после FLOODPLAIN — об Амазонке, после RAINFOREST — о Миссисипи. Для запуска до импорта L1 перед CHANNEL показываются необходимые факты из Level 1: названия материков/океанов, направления и их отличительные свойства. Это **временная программа предварительного ознакомления**, а не полноценный импорт Level 1.

## Использование именно авторских карт

Генератор теперь не использует искусственную географическую SVG-подложку, тайлы или преобразования из lon/lat.

- После CHANNEL → `assets/rivers-authored-2.webp`: исходная карта с добавленным Нилом.
- После FLOODPLAIN → `assets/rivers-authored-3.webp`: та же карта с Нилом и Амазонкой.
- После RAINFOREST → `assets/rivers-practice-step-3.webp`: та же карта с Нилом, Амазонкой и Миссисипи.

Карты были выделены из встроенных изображений оригинального PDF. Геометрия основы проверена сравнением ключевых точек: совпадает для всех трёх стадий с погрешностью изображения существенно меньше 1 px.

Якоря и стрелки хранятся в **процентах конкретного авторского изображения** (1587×1057). Масштабирование на телефоне сохраняет соответствие букв географии.

## Семантические подсказки

`data/rivers-semantics.js` содержит базовые географические якоря и три раздельных якоря для каждой изучаемой реки. У каждого якоря есть `regions[]` и редакторские `cues[]`. `engine/semantic.js` составляет подсказку только тогда, когда её целевая область соответствует **ровно одной выбранной букве**.

Например, фраза «in the Atlantic Ocean» не может назначаться, если одновременно выбрана метка для северной и южной Атлантики. Такая комбинация отклоняется, а не отдается ребёнку как неверный ответ.

Новый объект получает минимум 35% букв в тренировке; при недостаточном числе различимых якорей слишком длинное слово пропускается. Расстояния контролируются на минимальной карте шириной 300 CSS px. Порядковое числительное добавляется в каждую подсказку.

Это **проверка по размеченной семантической модели**, а не универсальный географический движок. Региональные отношения и описания каждого якоря всё ещё требуют редакторского утверждения автора.

## Правила зачёта и хранения

`engine/geowords.js` ведёт `schemaVersion:2`:
```json
{"courseId":"rivers","schemaVersion":2,"steps":{"nile":{"authoredSolved":true,"solvedWordIds":["aquifer"]}}}
```

- Завершение оригинального задания учитывается один раз.
- Практика не может засчитываться, пока не завершён исходный геоворд этого шага.
- Считаются только ID из `step.wordIds`; вымышленные/устаревшие/подменённые ID игнорируются.
- Переименование терминов допускается через явно заданный `course.wordAliases`, а не приём произвольных строк.
- Миграция экспериментального v1 в v2 не придумывает успешное прохождение оригинального геоворда.
- После финального 7/7 доступна повторная тренировка без начисления прогресса.
- 11 старых Mountains в `data/levels.js`, их растровые карты, схема размещения и прежние `localStorage`-ключи **не менялись**.

## Проверки

```sh
node --check app.js && node --check engine/geowords.js && node --check engine/semantic.js && node scripts/validate-levels.mjs && node scripts/validate-generator.mjs
```

CI проверяет:
1. Целостность прежних 11 Mountains.
2. Три оригинальных Rivers, оригинальные буквы и исходные изображения.
3. Две стрелки FLOODPLAIN и три RAINFOREST.
4. Три цикла «оригинал + 6 дополнительных» и автоматическое открытие следующего шага.
5. Повторные прохождения, поддельные ID прогресса и восстановление сохранения.
6. Семантику, расстояния и не менее 35% букв на новой реке.
7. **30 000** детерминированных сгенерированных вариантов без обнаруженной двусмысленности по размеченным регионам.

- Добавлена отдельная основа `engine/curriculum.js` с общими знаниями, подтверждением учебных экранов и зависимостями дескрипторов. Она пока не подключена к пилоту; реальный каталог фактов/мест/слов не утверждён. См. `docs/CURRICULUM.md`.
- 18 новых тренировочных слов и редакторские подсказки — **черновые**, ещё требуют одобрения автора; они не должны преждевременно раскрывать слова следующих авторских заданий.
- Требуется повторный независимый headless Chromium и реальный iOS-тест стрелок, маркеров, зума и визуальной читаемости. На iPhone именно этого коммита проверки пока нет.
- Миграция пилотного прогресса в Curriculum пока не выполняется. Основа ведёт `cleanCount`, но переход по-прежнему только по завершённым словам (`advanceOn: solved`).
- Существующая логика экранов Mountains должна остаться неизменной.

**Не мержить без повторного ревью и визуальной проверки авторских карт.** Следующее архитектурное продвижение: импорт полного L1 и L2, факты с моментами открытия, глобальный Curriculum. Утверждённое правило 1+6 не менять.
