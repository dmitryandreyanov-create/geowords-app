## Результат по исходным авторским PDF

Импортёр `tools/import_workbooks.py` изучает два исходных PDF с оригинальной графикой и извлекает карты **без нарисованных букв**, координаты исходных букв, полный текст подсказок, фрагменты следующих фактов и метаданные страниц.

| Раздел | Задания | Буквы | Подсказки | Разных карт | Пока не сопоставлено |
|---|---:|---:|---:|---:|---:|
| L1 — Continents & Oceans | 10 | 97 | 97 | 2 | 36 |
| L2 — Rivers | 10 | 90 | 90 | 8 | 33 |
| Итого | 20 | 187 | 187 | 10 | 69 |

Данные находятся в `data/import-staging/l1-staging.json` и `data/import-staging/l2-staging.json`. Карты в `assets/import-staging/`. Это **промежуточный авторский импорт, не игровые уровни**.

К каждому элементу привязаны исходный PDF и номер страницы, координаты в процентах соответствующей авторской карты, исходная буква и текст подсказки в правильном порядке (The first, second, ...).

### Почему 69 подсказок требуют проверки

Если буква, например N, повторяется несколько раз, PDF сам по себе не обозначает машинным ID, какая буква соответствует конкретной географической подсказке. Импортёр фиксирует все варианты `candidateMarkerIds` и оставляет `markerId: null`, а **не** назначает ответ наугад. Ещё 118 сопоставлений однозначны по буквам, но географическую корректность тоже следует проверить при редакторском импорте.

Из исходных PDF автоматически извлечены **55 векторных стрелок** (5 для L1 и 50 для L2), с точками начала и конца в процентах авторской карты. Стрелки видны в редакторе, но конечные географические соответствия всё ещё требуют авторского подтверждения. Промежуточные данные нельзя подключать в живую игру как завершённые уровни.

Факты на инструкционных страницах сохранены как `factsExtract` — пока необработанный текст. Для настоящего L1/L2 порядок открытия `learnBefore/unlockAfter` ещё не размечен. Отдельная основа общей модели знаний реализована в `engine/curriculum.js`, но к игре не подключена; см. `docs/CURRICULUM.md`.

### Повторный импорт

Исходные PDF не коммитятся в репозиторий. **Репозиторий сейчас публичный**: карты и тексты в истории Git доступны через GitHub независимо от того, включены ли они в деплой. Из папки проекта:

```sh
python tools/import_workbooks.py --l1 "Level 1 Oceans & Continents.pdf" --l2 "GeoWords Level 2 Rivers-2.pdf" --out /tmp/geowords-import
```

Необходимы `PyMuPDF` (`fitz`) и Pillow. Скрипт проверяет все **187** букв по мультимножеству букв ответа и число подсказок на страницах. `node scripts/validate-import-staging.mjs` проверяет зафиксированные данные, ссылки на карты и отсутствие автоматически подставленных неоднозначных ответов.

## Экран сверки для автора

Новый инструмент — **`tools/review-import.html`**. Он отдельно от детского приложения и не включает спорные задания в PWA.

Чтобы открыть локальную копию, выполни **одну строку** из корня ветки:

```sh
python3 -m http.server 8080
```

Открой `http://localhost:8080/tools/review-import.html`. Утилита сама загружает два проверенных JSON-файла и оригинальные карты, показывает все 20 заданий и тексты подсказок; никаких учётных записей или сервера приложений не требуется. Старый редактор удалён: поддерживается **один** экран `tools/review-import.html`.

Порядок: выбрать задание слева → подсказку справа → нужную букву на карте → периодически нажимать **«Экспорт разметки JSON»**. Жёлтые кандидаты имеют **одинаковую букву**, но географическую правильность выбирает человек по PDF, включая векторные стрелки. Нельзя присвоить один маркер двум подсказкам. Разметка автоматически сохраняется в локальном хранилище браузера. JSON-экспорт остаётся обязательной резервной копией (при запрете хранилища автосохранение недоступно).

**Экспорт совместим с `tools/apply_author_mapping.py`:** `assignments[puzzleId][cluePosition] = markerId`. Сохранение разметки выполняется автоматически в localStorage, если браузер разрешает запись. Для надёжной резервной копии периодически экспортируй JSON. При незавершённых 69 соответствиях команда `--require-complete` завершится ошибкой, и такие данные не будут опубликованы. Текущий `data/import-staging/review-assignments.json` содержит пользовательские **69/69** назначений; отдельные подтверждения географии в старом формате отсутствуют. Даже 118 первичных односимвольных совпадений нужно проверить на географическую корректность.

```sh
python3 tools/apply_author_mapping.py --staging data/import-staging/l1-staging.json data/import-staging/l2-staging.json --review geowords-l1-l2-reviewed-assignments.json --out mapped.json --require-complete
```

Для повторного импорта PDF необходимо сначала запустить `tools/import_workbooks.py` (см. выше). Команда не изменяет рабочие карты или исходные данные в GitHub. Старый дублирующий редактор удалён. Полное руководство: `tools/README-IMPORT-REVIEW.md`.

Проверки: `node scripts/validate-import-staging.mjs` и `node scripts/validate-import-review.mjs` теперь выполняются в CI; предыдущая версия экрана была проверена в Chromium, а новую версию с автосохранением и PDF-стрелками необходимо повторно проверить в браузере автора. Сами географические решения автора пока отсутствуют.

### Изоляция GitHub Pages

`node scripts/build-pages.mjs` создаёт каталог `dist/` по явному белому списку только файлов текущей игры. GitHub Pages публикует `./dist`, а не корень репозитория. В публичной истории GitHub остаются staging-данные, ответы и инструменты; для реальной конфиденциальности нужно изменить политику хранения либо видимость репозитория отдельно.

## Публикация

GitHub Pages собирается строго из списка игровых файлов (`node scripts/build-pages.mjs`) в каталог `dist/`; промежуточные JSON, оригинальные ответы, исходные инструменты и документы не входят в веб-артефакт. Важно: репозиторий `geowords-app` на момент проверки **public**, поэтому файлы остаются видимыми в GitHub и в истории коммитов. Ограничение Pages не является защитой содержимого репозитория.

Итог: **41 блок, 21 предполагаемый учебный экран, 5 сохранённых оговорок**, со строками-источниками, координатами, страницей PDF и SHA-256 исходника. Визуально сверены все 41 области.
